## 实施方案

用户已授权并发开发，代码基线为 f3cb81d。六个功能任务的代码已集成；主会话负责数据迁移、API/worker、审查及真实联调。当前只剩真实 Batch 结果下载等验收缺口；详见 [validation.md](validation.md)。管理员/归档、混合照片自动分组、统一确认入库、每张主要拍一本、全部默认 Batch/可切实时、可选联网、三类模型接通验证及 Agent UI 后续开发均已确认。状态 ready 表示可以据此进入开发阶段；本文件不宣称任何业务验收完成。

建议复用现有 Django/DRF 与 React；保持 `/baby/study`、会话认证及 CSRF。管理员管理共享书目，归档保留引用，再补写入 API。识别结果保存在私有草稿，业务服务在用户统一确认后验证及入库，模型本身不执行数据库写入。

手工新增与拍照新增同属管理员图书管理入口，上传、识别和确认接口均执行服务端管理员权限；不同管理员的原始照片/任务仍按创建者隔离。普通家长继续读取共享书目并管理自己的家庭书架。本期不额外设计普通家长提交书目候选的审核流程。

照片不要求用户预先分组。候选处理流程为逐图提取身份线索与照片类型 → 按版本证据自动匹配分组 → 聚合字段/查找冲突 → 用户核对/可选联网 → 统一确认保存。优先以可解释的 ISBN/版本及可见文字关联照片，视觉相似性或模型猜测不能独立作为合并依据；模糊和无归属照片明确保留。首期不做单张多本书定位/拆分。流程中的模型次数、Batch 阶段和重试应计入整体费用；识别任务无论单本/多本均默认 Batch，实时由用户主动选择，不按书籍数量自动切换。

新增统一服务端模型模块（计划 `backend/ai/`），由调用场景选择文字/图片/音频模型与实时/Batch 通道；配置包括服务端密钥、各通道地址、模型、超时和重试限制。三类能力都需要实际验证，Agent 页面不在本期。

Batch 需要持久化任务和逐本请求映射，独立处理成功与失败结果。先评估数据库任务表配合独立管理命令/worker 的最小方案，是否引入队列在确认规模和运维方式后选择；不能依靠页面长连接或请求进程驻留等待。

现有 `catalog/enrichment` 仅用于复用可靠的来源、身份及人工修正规则；前台联网检索仍需候选检索适配，不直接把 Excel 采集命令当作同步 API。照片证据应以真实的媒体引用及提取记录表达，不硬塞成网页来源 URL。

## API 和数据契约（公共契约已实施）

以下均沿用 `/baby/study`，实施详情见 [contracts.md](contracts.md)：

| 行为 | 候选接口 | 核心约束 |
| --- | --- | --- |
| 手工新增/归档 | `POST /books`、`DELETE /books/{id}` | 管理员、CSRF、幂等新增；DELETE 是归档，保留引用，不复用 legacy 状态 |
| 上传混合照片/查看任务 | `POST /book-intakes`、`GET /book-intakes`、`GET /book-intakes/{id}` | mode 默认 batch；媒体/照片/草稿按创建者隔离；管理员才可最终写共享书目 |
| 纠正分组/编辑草稿 | `PATCH /book-intakes/{id}/groups` | 合并/拆分/移动照片及字段修正；检查草稿 revision，防止迟到结果覆盖人工修改 |
| 可选联网候选 | `POST /book-intakes/{id}/enrichment` | 明确选择分组/字段；来源和版本候选独立保存，不自动确认为书目事实 |
| 统一确认入库 | `POST /book-intakes/{id}/confirm` | 先校验所选全部草稿、重复/ISBN/版本，再事务保存；未通过校验不产生半批书目；排除不确定组后可确认其他组；入库请求幂等 |
| 取消/失败项重提 | `POST /book-intakes/{id}/cancel`、`POST /book-intakes/{id}/retry` | 不取消已确认事实；仅重提失败步骤，迟到结果保持草稿状态，不自动入库 |

逐图提取结果应携带 photo_id、照片类型、可见身份字段、对应证据及冲突；分组结果携带 group_id、photo_ids、版本候选、未归属照片、字段来源和 revision。Batch 请求使用持久化 custom_id 映射到照片/分组/处理阶段，禁止仅按结果行号关联。确认结果返回已有/新建书目映射，个人书架是否加入单独明确选择。

## 风险、迁移与延期安排

- 删除/归档状态不能复用现有 `legacy`：后者是历史导入映射，业务含义不同。若采用归档，单独设计字段/状态及历史显示；迁移保留 ID、来源、系列关系及原书架状态。
- 照片来源与模型候选需要独立证据/媒体表示；现有网页来源约束不适合直接代替私有图片。手工入库不能受历史 Excel 来源唯一约束误伤。
- Batch 时间窗口和 JSON 输出参数存在官方文档差异，真实联调才能确定；文件默认 30 天保留不等于本地媒体保存策略。Base64 会增加 JSONL 体积，分批策略需按限制和样本验证。
- 重试/取消/重复下载会造成重复费用或重复资料；保存与回填需幂等，不在不确定提交状态下无限重提。
- 模型无法可靠补全照片以外的事实；版本不明仅保留候选，未知阅读属性留空。共享书目管理与个人识别任务权限分别验证。
- 家长 Agent 交互界面经用户确认后续开发；连续语音通话、语音合成、完整 Agent 编排和套装自动拆分不纳入本期。三类模型适配和验证均保留；单张多本经用户确认不纳入首期。
- 新增图书可选联网补全已确认，TASK-007 纳入候选实施范围；未实施、未验证，不默认为已交付。
- 自动分组增加逐图身份识别、匹配和合并的复杂度；版权页无法独立确认归属时保留疑点，同套装 ISBN 不代表同一本书。需要真实照片样本验证准确性及费用。
