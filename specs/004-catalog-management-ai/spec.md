## 背景与目标

- 用户希望直接在系统书目页面维护图书，减少切换 Django 管理后台的操作。
- 通过书籍照片生成可用于录入的图书资料，减轻手工抄写负担。
- 接入用户指定的 MiMo 服务，利用批量推理节约可等待任务的成本，并为后续家长 Agent 交互提供文字和语音理解能力。
- 当前完成需求讨论、官方文档核对、规格及实施任务拆分；主要范围已由用户逐项确认。本轮不实施业务代码、不创建开发会话，下一开发阶段按计划创建多个 Codex 会话。

## 现状、依赖与历史范围变化

以下是代码核对所得现状，不构成新增需求：

- `Book`、`BookSeries` 是共享书目；`ShelfItem` 按用户隔离。目前前台只读书目，新增和编辑在 Django 后台进行。
- 系列成员、家庭书架使用受保护的图书引用；删除规则需要明确，不能以直接物理删除替代产品设计。
- 003 已有字段来源、具体版本、人工修改保护及采集/导入能力；新增图书不会自动联网，采集命令也不是现成的前台检索服务。
- 当前来源证据主要记录网页 URL。照片、模型提取和用户确认需要新的来源表达，不能伪装成官方网页核验。

依赖 [002 系列书架](../002-series-shelf/spec.md)、[003 图书资料](../003-catalog-enrichment/spec.md) 及仓库认证、CSRF、数据隔离、已完成评估不可修改等约束。

历史资料中 [产品范围](../../产品讨论/product.md) 将自动识别上传绘本排除在第一版之外，[技术方案](../../产品讨论/技术方案.md) 将书目写入限定为 Django 后台并把模型接入安排在后续阶段。本轮用户明确提出并澄清前台图书管理、照片资料解析及 MiMo 接入，当前范围以本 Spec 为准；这不等于新增 AI 绘本内容解读。旧资料保留为历史来源，已追加当前范围说明；尚未实施的功能不描述为当前系统能力。

## 范围与非目标

用户明确要求：前台新增/删除系统图书；拍照解析图书信息；MiMo OpenAI 兼容接入和 Batch 能力；文字生成、图片理解、语音理解能力；先讨论，确认后以多个 Codex 会话开发。

本轮用户后续已确认：只有管理员管理共享书目，删除按归档处理；用户可混合上传图书照片，由系统识别同一本书的多张照片并自动分组归纳；识别后提供可选联网补全，展示来源并确认。

第二轮已确认：自动分组后统一确认入库、疑点可纠正；首期每张照片主要拍一本书，可混合上传不同书的照片；本期图书识别任务全部默认省钱 Batch（包括单本），用户可切换实时，不再采用“单本默认实时”的 Agent 提案。未来 Agent 对话的调用方式单独设计。

第三轮已确认：本期实际接通并验证文字生成、图片理解、音频理解三类能力，家长 Agent 交互界面后续开发。

当前首期范围与实施建议：

- 前台支持手工新增、拍照录入和归档删除；已入库图书的通用编辑、误删恢复暂作后续候选，不作为本次必需验收。识别草稿编辑和分组纠正属于已确认范围。
- 混合照片自动分组，无需用户预先按书分组；所有图书识别默认 Batch，用户可切换实时，已由用户确认。
- 模型结果先形成可编辑草稿，用户统一确认后写入书目，已由用户确认；可选择一并加入自己的书架是 Agent 建议。
- 服务端交付并验证文字、图片、音频理解三个调用入口；家长聊天/录音页面和 Agent 业务后续开发。文字流式响应及工具调用适配为后续可扩展方向，本期不承诺完整 Agent 编排。
- 可选联网补全已由用户确认纳入本次需求。

首期经用户确认不包含一张照片同时识别整排书脊或多本封面；每张照片主要拍一本书。用户确认家长 Agent 交互界面后续开发。Agent 据此提出的边界：本期不增加完整 Agent 编排/记忆/自动计划调整、连续实时语音通话、语音合成或音色克隆；套装自动拆分和推断未拍摄分册不属于当前图书资料录入范围，后者也不符合资料不可编造约束。

## 建议行为细节（尚未定稿）

1. 在系统书目点击“新增图书”，选择手工录入或拍照/上传；手机相机入口在支持的浏览器中调用相机，其他情况使用文件选择。实际相机访问需要 HTTPS 或受信任的本地环境，部署时验证。
2. 用户混合上传不同书籍的封面、封底、ISBN 和版权页。系统先提取每张照片的书名、ISBN、作者、出版社/版本及照片类型等身份线索，再跨照片自动分组，聚合同一本书的字段。不要求用户预先建组，也不能按上传顺序或相似书名直接合并。
   - 同 ISBN 且版本一致可以作为强匹配线索，但套装 ISBN、封底宣传的其他书 ISBN、识别错误需区分；同名异版、同套装不同分册保持独立。
   - 缺少身份线索、照片属于多个候选或字段冲突时，保留未归属/待确认照片，提供合并、拆分及移入其他分组入口；不能强行归组。用户已确认允许纠正疑点；补拍入口为 Agent 方案。
   - 自动分组可能需要先逐图提取，再跨图匹配及聚合；Batch 模式可能包含多个处理阶段，等待时间与费用需覆盖全部阶段，不能只计算最后一次图书提取。
3. 生成草稿：书名、原文名、语言、作者/绘者/译者、ISBN、出版社、出版时间、装帧/页数、版本说明，以及照片中实际出现的系列线索。仅提取可见内容；候选与冲突明确标识。
4. 用户可以补拍、修改或选择可选联网补全；保留“照片识别”“外部来源”“人工录入/修正”的不同证据类型。用户确认不自动等同于权威来源核实。
5. 保存时校验 ISBN 与单本/套装类型，按具体版本检查重复。候选重复允许选择已有图书，冲突需人工确认；提交幂等，模型结果和网络重试不能产生重复书目。
6. 用户确认入库后，可自行选择加入家庭书架；新建系统图书不自动表示“已拥有”。套装没有可靠成员清单时，只保存套装候选或提示补充，不能凭模型推断创建分册。
7. Batch 页面显示识别照片/归纳分组/待确认/部分失败/已结束等用户可理解状态，以及逐本结果。刷新页面、后端重启及乱序返回不丢失照片和分组映射；任务取消、草稿废弃后，迟到结果不自动入库。所有候选须用户统一确认后保存。
8. 未配置密钥、额度不足、限流、图片模糊或结果无效时，显示具体下一步（重拍、改为手工、稍后重试），保留已上传分组和已有编辑。照片保留时长、封面用途、清理时机需要在实施前确定。

## 已确认决定与实施前配置

第一轮已确认：

1. 用户选择只有管理员管理共享书目，删除按归档处理。影响 REQ-001/007/009。
2. 用户要求混合上传照片，自动识别单本多图并分组归纳入库，修正原先人工预分组提案。影响 REQ-002/010/014。
3. 用户选择识别后提供可选联网补全，展示来源并确认。影响 REQ-008/012。

第二轮已确认：

1. 自动分组后统一确认入库，疑点可纠正。影响 REQ-010/014。
2. 首期支持混合上传，每张照片主要拍一本书，不做单张多本识别。影响 REQ-002/014。
3. 全部默认省钱 Batch，可切换实时。影响 REQ-004/011；原单本默认实时提案不再有效。

第三轮已确认：三类能力都实际接通验证，Agent 交互界面后续做。影响 REQ-005/013。

以下为实施配置或后续候选，不阻塞当前范围：

- 实时/Batch 可接受等待体验，尤其混合照片逐图识别再归组可能需要多个异步阶段。
- 通用编辑、误删恢复、独立系列/套装维护不计入本次必需验收；后续讨论时追加需求，不从现有代码反向推断范围。
- 原始照片先保持私有，不默认发布原图；照片不因确认书目而自动成为共享封面。若使用用户照片作共享封面，需要独立明确选择和媒体访问规则。保存时长、每批数量和单图限制以可配置实现方案及验证记录明确。
- 实时地址、Batch 地域地址、可用型号及预算由用户配置提供；讨论阶段无需密钥。文档内的等待窗口/JSON 参数差异在受控联调中解决。
